# ПОС — Преподавательская оценка студентов

## О проекте

ПОС (Преподавательская Оценка Студентов) — консольное приложение для управления студентами, рубрикаторами оценивания, критериями, оценками и итоговыми результатами.

Проект разработан в рамках домашнего задания №2 по дисциплине «Конструирование программного обеспечения» с использованием принципов Domain-Driven Design (DDD), слоёной архитектуры и паттернов проектирования GoF.

## Возможности

- **Управление студентами:** добавление, просмотр и удаление студентов.
- **Управление рубрикаторами:** создание, просмотр и удаление рубрикаторов.
- **Управление критериями:** добавление, просмотр и удаление критериев оценивания.
- **Управление оценками:** выставление, просмотр, изменение и отмена оценок.
- **Расчёт итогов:** вычисление итоговой оценки на основе выставленных баллов и весов критериев.
- **Отчётность:** просмотр подробных отчётов по студентам.
- **Экспорт:** сохранение отчётов в форматах CSV и JSON.
- **Хранение данных:** сохранение информации в JSON-файлах.

## Архитектура

В проекте используется упрощённая Clean Architecture (чистая архитектура).

Основной принцип — разделение ответственности между слоями и направление зависимостей внутрь, к доменной модели.

### Слои приложения

**1. Domain — доменный слой**

Содержит основную бизнес-логику приложения:

- Доменные сущности.
- Объекты-значения.
- Проверку бизнес-инвариантов.
- Доменные сервисы.

Доменный слой не зависит от консольного интерфейса, файловой системы и других внешних компонентов.

**2. Application — прикладной слой**

Отвечает за выполнение сценариев использования:

- Управление студентами.
- Управление рубрикаторами.
- Управление оценками.
- Формирование отчётов.
- Взаимодействие с репозиториями через абстракции.

**3. Infrastructure — инфраструктурный слой**

Реализует технические механизмы приложения:

- Хранение данных в JSON.
- Реализацию репозиториев.
- Экспорт отчётов в CSV и JSON.
- Регистрацию инфраструктурных зависимостей.

**4. CLI — пользовательский интерфейс**

Обеспечивает взаимодействие с пользователем через консоль:

- Главное меню.
- Управление студентами.
- Управление рубрикаторами.
- Управление оценками.
- Просмотр и экспорт отчётов.

Здесь также выполняется настройка Dependency Injection и связывание компонентов приложения.

### Направление зависимостей

```text
             Pos.Cli
                |
                v
         Pos.Application
                |
                v
           Pos.Domain

       Pos.Infrastructure
                |
                v
        Реализация абстракций
```

Внешние слои зависят от внутренних абстракций. Доменная модель не зависит от инфраструктуры.

## Domain-Driven Design

При разработке использовались основные концепции предметно-ориентированного проектирования (DDD).

### Ubiquitous Language — единый язык предметной области

В проекте используются следующие основные понятия:

- **Студент (Student)** — человек, чьи результаты оцениваются.
- **Рубрикатор (Rubric)** — набор критериев оценивания.
- **Критерий (Criterion)** — отдельный параметр оценивания с максимальным баллом и весом.
- **Оценка (Evaluation)** — результат оценивания студента по конкретному критерию.
- **Итоговая оценка (Final Grade)** — вычисленный результат на основе выставленных оценок и весов критериев.

### Сущности (Entities)

Основные доменные сущности:

- `Student`
- `Rubric`
- `Criterion`
- `Evaluation`

Сущности обладают уникальными идентификаторами и представляют объекты предметной области.

### Объекты-значения (Value Objects)

Для инкапсуляции значений и проверки их корректности используются:

- `Score` — представляет числовую оценку.
- `Weight` — представляет вес критерия.

Объекты-значения обеспечивают проверку допустимости значений при создании.

### Инварианты

Доменная модель обеспечивает соблюдение следующих правил:

1. Оценка не может быть отрицательной.
2. Оценка не может превышать максимальный балл соответствующего критерия.
3. Оценку можно выставить только по критерию, принадлежащему выбранному рубрикатору.
4. Итоговая оценка должна рассчитываться на основе существующих оценок и актуальных весов критериев.

### Репозитории (Repositories)

Для отделения бизнес-логики от механизма хранения используются абстракции репозиториев.

Они позволяют работать с данными студентов, рубрикаторов и оценок независимо от конкретного способа хранения.

Реализации репозиториев находятся в инфраструктурном слое.

### Доменный сервис (Domain Service)

`GradeCalculator` отвечает за вычисление итоговой оценки студента.

Расчёт учитывает результаты оценивания и веса соответствующих критериев.

Таким образом, итоговая оценка не хранится как произвольное значение, а вычисляется на основе доменных данных.

## Паттерны проектирования GoF

В проекте используются паттерны трёх категорий GoF.

### 1. Порождающий паттерн — Factory

**Назначение:** централизованное создание объектов оценки.

Фабрика отвечает за создание корректных объектов `Evaluation` и позволяет сосредоточить проверки доменных правил в одном месте.

Это помогает избежать создания некорректных объектов из разных частей приложения.

### 2. Структурный паттерн — Facade

**Класс:** `PosFacade`

Фасад предоставляет единую точку взаимодействия с основными операциями приложения.

Он скрывает внутреннюю сложность взаимодействия сервисов студентов, рубрикаторов, оценок и отчётов от консольного интерфейса.

Благодаря этому CLI не должен самостоятельно координировать работу всех прикладных сервисов.

### 3. Поведенческий паттерн — Strategy

**Интерфейс:** `IGradeReportExporter`

Реализации:

- `CsvGradeReportExporter`
- `JsonGradeReportExporter`

Стратегия позволяет выбирать способ экспорта отчёта в зависимости от требуемого формата.

При необходимости можно добавить новые форматы экспорта без изменения основной логики формирования отчётов.

## Dependency Injection

Для управления зависимостями используется `Microsoft.Extensions.DependencyInjection`.

Контейнер зависимостей отвечает за создание и связывание необходимых компонентов приложения.

В него регистрируются:

- Прикладные сервисы.
- Доменные компоненты.
- Реализации репозиториев.
- Экспортёры отчётов.
- Фасад приложения.

Настройка зависимостей выполняется при запуске приложения, что позволяет отделить создание объектов от бизнес-логики.

## Хранение данных

Данные приложения сохраняются в JSON-файлах:

| Файл | Содержимое |
|---|---|
| students.json | Информация о студентах |
| rubrics.json | Рубрикаторы и критерии |
| evaluations.json | Выставленные оценки |

Хранение данных отделено от доменной модели с помощью репозиториев.

Это позволяет в будущем заменить механизм хранения без необходимости переписывать основную бизнес-логику.

## Отчёты и экспорт

Приложение поддерживает просмотр и экспорт отчётов по студентам.

Доступны два формата:

- CSV — для работы с табличными данными.
- JSON — для структурированного хранения и дальнейшей обработки.

Отчёты содержат информацию о студенте, рубрикаторе, критериях, максимальных баллах, весах, выставленных оценках и итоговом результате.

Экспортируемые файлы сохраняются с использованием кодировки UTF-8.
